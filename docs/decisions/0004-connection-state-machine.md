# 0004 — Connection lifecycle as a state machine

Status: accepted on 2026-09-04.

`apps/web/src/lib/connection-machine.ts` models one socket attempt as a schema-first state machine built with `effect-machine`: `Connecting`, `Open` carrying `openedAt`, and the two final states `Ended` and `Failed`. `realtime-client.ts` creates the socket, drives the machine from four DOM listeners through its synchronous client, and maps the machine's output to the success or failure of that attempt.

The previous shape carried a `settled` boolean so a second resume could not fire, and an `openedAt: number | null` recording whether the socket had ever opened — two fields encoding one fact, free to disagree with each other. Both are now states: a second `Opened` while `Open` has no registered transition, and `openedAt` exists only where it means something. One subtlety is worth recording because it is easy to get backwards: a close before `STABLE_SESSION_MS` is a _failure_, not a clean end. Reporting it as success would send the program straight back around `Effect.forever` with no delay and rebuild the accept-then-drop storm the threshold exists to prevent.

The objection to this change is real and was raised by the author of the code it replaces: `AGENTS.md` gives Effect "resources, and service lifecycles", and `docs/research/original-research.md` warns that dual frameworks are how starters rot. The line that answers it is that retry is not modelled here. `reconnectSchedule`, `Effect.retry` and `Effect.forever` still decide whether and when another attempt happens, and `reconnectSchedule` is still exported so `apps/web/test/reconnect-schedule.test.ts` reads the real policy rather than a copy. The machine answers which states exist and which transitions are legal; Effect still owns the lifecycle those states sit inside.

Socket ownership moved from `Effect.callback` to `Effect.acquireRelease` in the same change, and that is the larger practical win. `Effect.callback`'s finalizer runs only on interruption, so every path that resumed had to release the socket itself, and a missed path leaked one socket and four listeners per attempt. `acquireRelease` releases on success, failure and interruption alike, which turns that from something a reader must remember into something the runtime guarantees. Detaching the store moved into the same release and still takes the socket it is tearing down, so a superseded attempt cannot clear a connection a later one established.

`effect-machine` is pre-1.0, pinned exactly at `0.25.1`, and its peer range names this repository's exact Effect RC. The scoped `@humanlayer/effect-machine` package was evaluated first and rejected: it still declares a beta-era peer range against an Effect this repository does not install.
